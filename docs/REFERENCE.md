# Implementation reference

For installation and everyday usage, start with the repository [README](../README.md).

A local computer-use prototype for Pi: a Rust daemon (`daemon/`) and a Pi project extension (`.pi/extensions/computer-use/`) communicate over a Unix-domain socket. The extension registers these tools: `desktop_observe`, `desktop_changes`, `desktop_batch`, `desktop_dirty_regions`, `desktop_search_seen`, `desktop_metrics`, `desktop_launch_app`, `desktop_click`, `desktop_double_click`, `desktop_drag`, `desktop_focus_window`, `desktop_inspect_visual`, `desktop_set_text`, `desktop_type`, `desktop_keypress`, `desktop_scroll`, `desktop_inspect`, `desktop_screenshot`, `desktop_wait`, `desktop_stop`, `desktop_ping`, `desktop_request_user`, `desktop_visual_permission`, and `desktop_model_phase` (24 registered desktop tools; 21 daemon tools). The model loadout is 3 tools while OFF, 17 basic tools while ON, plus phase handoff in hybrid. Exact visual grants temporarily activate their capture tool; duplicate convenience actions remain usable through batch rather than standalone declarations. `desktop_observe` and `desktop_changes` return the current X11 EWMH `windows` list alongside the accessibility tree/delta; pass `screenshot: true` to observe to include an image only after an exact single-use `desktop_visual_permission` grant. `desktop_screenshot` captures the full screen or a rectangular region. See [PROTOCOL.md](../PROTOCOL.md) for the daemon IPC commands and response format.

## What it does (and does not)

- Reads accessible UI structure through AT-SPI and independently lists X11 EWMH client windows (id, title, active, and bounds when available) on every observe/changes call. An inaccessible application still appears as an X11 window, **not** as fabricated semantic nodes. Isolated Firefox testing now verifies accessible local-page controls on the installed build; it does not repair an already-running inaccessible browser. See [desktop diagnostics](DESKTOP-CAPABILITIES.md). The active X11 window is included even if missing from the client list. Window changes are read on each call and do not advance the semantic generation or trigger `desktop_wait`. Captures the X11 root window as PNG only when requested, and can optionally capture a region.
- AT-SPI proxies disable zbus property caching and read individual properties, never an implicit `Properties.GetAll`. This avoids a reproduced Brave/Chromium accessibility-bridge abort when marshalling all properties. A private-bus regression and the [disposable Brave matrix](brave-isolation-findings.md) cover the fix; no browser profile or settings changes are required. HTML entries may still reject AT-SPI `EditableText`, so Unicode semantic text setting is not universally supported.
- `desktop_focus_window` sends an EWMH pager-source activation request and verifies the actual `_NET_ACTIVE_WINDOW` for up to one second, checking Stop while waiting. A refused request or vanished target returns an error rather than a false success. It never sends a close request or synthetic click.
- Registers AT-SPI event interests with the registry as well as D-Bus signal matches. If event registration is unavailable, a bounded semantic invalidation fallback is used; there is no continuous screenshot polling. Showing dialogs are discoverable even when another window remains focused.
- `desktop_launch_app` dispatches a visible installed desktop entry through native GIO by exact desktop ID basename (`app_id`, e.g. `brave-browser.desktop` if installed) or exact localized display `name`. It accepts neither executable commands nor paths/arguments. If a name matches multiple entries, it returns up to 20 `{app_id,name}` choices without launching; use an unambiguous ID. A successful `launch: {app_id,name,accepted:true}` means GIO accepted dispatch, **not** that a window opened or is ready: wait/observe afterward. Prefer it over navigating the launcher when the installed entry is known; when using Cinnamon's menu instead, select actual observed AT-SPI controls, never guessed semantic IDs. No live menu selection is verified here. Stop rejects subsequent launches at their safety gate but cannot cancel a launch already past its final check; uncertain dispatch outcomes must not be retried automatically. Cinnamon selection and model scoping preserve a real showing shell popup alongside another active window only with observed AT-SPI evidence; probing is bounded to 180 ms, and idle/hidden shell trees remain pruned.
- Sends pointer and keyboard input using XTEST. Text entry uses the current X keyboard map; it does not use a clipboard or implement an IME.
- Communicates with newline-delimited JSON. The default socket is `$XDG_RUNTIME_DIR/pi-computer.sock`, falling back to `/run/user/<effective-uid>/pi-computer.sock`. `COMPUTER_USE_SOCKET` overrides this; the daemon sets the socket mode to `0600`. Set the override consistently for daemon and client.
- This is an X11 implementation, not a Wayland implementation. Semantic observation and accessibility-node operations require a working session D-Bus and AT-SPI registry; without AT-SPI, observe/changes return an empty semantic tree and the X11 windows. Window titles can be used with `desktop_focus_window` (which requires XTEST), or use absolute coordinates for physical input; window IDs are not accessibility node IDs. No screenshots are taken for the window list. Screen capture requires a reachable X server; input also requires XTEST.
- `desktop_batch` executes up to 24 ordered actions/checks in one socket round trip, including exact semantic selectors, event-driven waits and immediate `assert` checks for live name/value/enabled/visible/focused. Malformed assertions are preflighted across the batch; missing/ambiguous targets, unreadable expected values and mismatches fail safely. Password values are refused. Each assertion forces a fresh bounded AT-SPI scan and returns checked expected/actual fields (or a readback-omission marker under text overflow). It stops at the first error by default. Actions are not rolled back. `desktop_dirty_regions` compares xxHash3 hashes of 64×64 tiles over the **whole X11 root**, merging adjacent changed tiles into absolute `{x,y,width,height}` rectangles; it returns metadata only, with no PNG/image to the model. The first check or screen resize returns `baseline:true` and one full-screen rectangle; unchanged screens return `regions:[]`. At most 64 merged rectangles are returned; more are summarized as a single conservative bounding rectangle (`summarized:true`). It is on-demand and still reads one raw full-root frame per check: root XDamage hints are not a complete stream under Cinnamon's compositor. An animation, caret blink, clock, or pointer motion can legitimately mark tiles dirty; a region is a pixel change, not a claim about its cause.
- `desktop_search_seen({query, limit?})` searches a daemon-lifetime, in-memory index of previously observed AT-SPI names, roles, window context, IDs, bounds, and last-seen timestamps. It retains at most 2,000 entries for 30 minutes, returning 10 `current`/`stale` hints by default (maximum 50). Exact names rank ahead of prefixes/token/substrings, with current and recent hits preferred within equal match quality. Unchanged observations refresh timestamps without rebuilding the index. Editable field names/values and images are excluded; public UI names and window titles can still themselves contain sensitive information, so this is not a privacy guarantee. A historical ID is **never** sufficient to authorize an action: observe and revalidate the current accessibility node first. The index is cleared by daemon restart, survives separate Pi client sessions, and is never written to disk.
- For full-root dirty-region checks, capture reuses a bounded MIT-SHM shared-memory buffer on local X11 and falls back to core X11 `GetImage` when unavailable. Dirty checks hash native pixel bytes directly, ignoring undefined XRGB bits and row padding, without a full-frame RGBA intermediate; screenshot encoding still uses decoded RGBA. Both read the **entire root**; MIT-SHM changes transport, not the set of pixels scanned. The daemon also attaches XDamage to the root drawable to collect hints, but Cinnamon/Muffin can repaint redirected child windows and compositor output **without root damage**. It therefore deliberately verifies each `desktop_dirty_regions` request with a full-root capture (`capture_mode:"full_root"`); the partial capture implementation remains disabled until a complete damage source can be established. Do not mistake XDamage availability for a bandwidth reduction. The optional visual feedback overlay uses X Shape and X Render.
- `desktop_metrics({reset?:boolean})` returns bounded stage counters and recent p50/p95 timings for IPC, locking, AT-SPI, indexing, capture, native hashing and merging. `reset:true` returns the measured interval then clears it. Metrics contain no UI text or pixels and are excluded from ordinary responses. Model-facing observations are scoped to an exactly matching active accessible window when safe; otherwise they default to 24 top nodes. A 6,000-character observation budget preserves valid JSON, generation, active window, top actionable nodes and explicit omission counts. Missing controls remain available through history search and live inspection.
- Action tools acknowledge the requested action and invalidate the accessibility cache; they do not return a refreshed tree. The next observe/changes/wait refreshes the tree and computes the delta. The on-demand visual cache captures bounded crops per request and returns changed tiles; it does not poll in the background or use XDamage.
- **Ctrl+Alt+Esc** is the primary emergency input-stop hotkey. If the primary X11 grab is unavailable (for example, another client owns it), the daemon tries **Ctrl+Alt+Shift+Escape** instead and logs the fallback choice at startup. Like `desktop_stop`, the active hotkey permanently disables daemon input until restart, **but does not stop the daemon process**. `desktop_ping` reports `input_stopped: true` after the hotkey fires. Stop now bypasses the daemon action mutex; native gestures cooperatively check it between events and best-effort release their own synthetic keys/buttons. A stop acknowledgement does not mean an in-flight action has already completed cleanup. Physical typing is limited to 16,384 characters; semantic editable text is not subject to that physical limit. An input timeout/disconnect has an uncertain outcome and must not be automatically retried. To re-enable input, deliberately stop the running daemon (Ctrl+C if foreground; terminate your own daemon process if it was lazily started) and restart it manually with `scripts/run-daemon.sh`. Pi will not automatically restart it after a reported Stop. If neither X11 hotkey grab is available, a warning is logged and `desktop_stop` remains available.
- No system service or privilege escalation is installed. Pi can start the daemon lazily on the first desktop tool call; user-local installation is sufficient.

The Pi extension keeps the breathing blue edge glow and live-pointer halo active for the **whole computer-use workflow**, including model thinking between tool calls. The first desktop tool execution (except `desktop_ping`, `desktop_metrics`, or `desktop_stop`; `desktop_launch_app` acquires the normal lease) acquires an internal 30-second activity lease and renews it every 10 seconds. `agent_settled` (not intermediate `agent_end`), run cancellation, shutdown/reload, and Stop close it. Lost renewals expire automatically, so a crashed client cannot leave the glow on indefinitely. Stop is never delayed by pending lease cleanup and cannot re-enable input. An older daemon without the lease command produces a one-time warning; desktop tools still work, but workflow-wide light is unavailable until the daemon is updated.

Standalone daemon input actions still own scoped activity tokens, and input-bearing batches retain them across waits and final observation. These coexist with workflow leases; one client's disconnect cannot unmap another's activity. Capture temporarily suspends and X11-syncs the overlay, then resumes the same animation phase if any action or lease remains active. This confirms X-server unmapping, not a presentation fence from every asynchronous compositor; final-frame capture isolation is compositor/driver-dependent. The overlay window is labelled `Pi computer-use feedback` for inspection and has an empty input shape. A daemon read-only request by itself does not start an action token; the Pi workflow lease is what covers observations and thinking.

The implementation is intentionally bounded: accessibility traversal is capped and semantic observations are cached/diffed. This is an X11 prototype, not a general-purpose desktop automation framework; accessibility depends on AT-SPI support in each application and input tools affect the active desktop.

## Requirements

Linux with an X11 session (including the XTEST extension), Rust/Cargo, Python 3 for the IPC check/benchmark, and Pi with support for local extensions. AT-SPI support also needs a usable session bus and accessible applications.

On Linux Mint/Ubuntu, install the system packages with:

```sh
sudo apt update
sudo apt install build-essential pkg-config libglib2.0-dev python3 at-spi2-core x11-utils
```

Install Rust using rustup (rather than relying on an older distribution Cargo):

```sh
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
. "$HOME/.cargo/env"
```

Cargo is often at `~/.cargo/bin/cargo`; project scripts check there when it is not on `PATH`. `libglib2.0-dev` provides the GIO/GLib/GObject linker libraries for the native desktop-entry launcher; no additional Cargo network dependency is required. No root privileges are needed to build, install, or run the project after prerequisites are installed.

## Quick start

From the repository root:

```sh
scripts/install.sh     # builds the release binary (one-time)
# scripts/run-daemon.sh  # optional foreground start; Pi can start it on first tool use
```

`install.sh` builds a release binary, installs it to `~/.local/bin/pi-turbo-daemon`, and copies the default config to `~/.config/pi-computer/config.toml` (or `$XDG_CONFIG_HOME/pi-computer/config.toml`) if absent; it never overwrites an existing config or installs a service. `run-daemon.sh` runs the repository **release** build via Cargo in the foreground (`COMPUTER_USE_BUILD_PROFILE=debug` opts into the slower development build) and loads `config/default.toml`. On the first desktop tool execution, the extension connects to the configured socket; if it is absent/refused, it starts the repository **release binary** (or the installed binary if the release build is absent). It never builds, executes a shell/script, or starts a background supervisor. A running daemon is left alone. Merely running the daemon does **not** expose its tools to Pi. Set `COMPUTER_USE_SOCKET` consistently for both if using a non-default socket. Building this Rust daemon is **not** a Pi build.

### Load into your existing Pi session

Add the absolute extension path to the existing `extensions` array in `~/.pi/agent/settings.json`, preserving your other settings and extension entries:

```json
"extensions": ["/absolute/path/to/pi-turbo-computer-use/.pi/extensions/computer-use/index.ts"]
```

Then run **`/reload` in the current Pi**. No Pi rebuild or separate session is required. This personal path works even when Pi's working directory is outside the repository. The host supplies the `typebox` dependency; `tests/test-real-pi-load.mjs` verifies actual Pi loading without mocking the import.

Use `/computer-use toggle` (or `/computer-use on` / `/computer-use off`) to enable persistent computer-use mode in **this same Pi session**. While ON, a theme-aware line above the editor shows `──────── Computer use ON ────────` and normal messages receive the desktop operating rules automatically: no slash-command prefix is needed for every task. The line fits the terminal width and disappears when OFF. The boolean is saved in a non-model custom session entry and restores on `/reload` and branch navigation. **A fresh Pi startup, including opening a saved session, defaults OFF**; new/resume/fork session replacements also default OFF. A reset is recorded so a later reload cannot resurrect an older ON entry. OFF blocks registered desktop observations/actions and task submission, except emergency Stop and metadata-only ping/metrics. It does not cancel an already-running tool, revoke issued input, restart a daemon, or reset emergency Stop. The agent must never auto-enable it. Toggling/help/model summaries never start a daemon, model call, glow, or notification process.

The ON bar also shows a live monotonic timer (`Computer use ON · 00:12`) and then retains the last duration (`Computer use ON · time: 00:23`). It starts at `before_agent_start`, before model thinking and the first desktop action; it does not count time waiting in Pi's input queue. Retry/compaction/follow-up continuations share the original timer until final settlement. OFF-mode UI tasks are blocked before tool execution. TUI refresh is once per second only during a visible active timer; idle/OFF, abort/Stop, settlement, reload, and shutdown clear it. Abort freezes immediately and tags the saved last duration `(abort)`, without a notification. Duration/outcome metadata (no prompt/UI content) follows the session branch and survives reload; incomplete measurements are discarded on shutdown/reload. Timers and toggles are **per Pi extension runtime/session**, not global. The desktop daemon/input mutex, root display, and emergency Stop are shared: running desktop workflows from different Pi sessions can interleave and are not isolated desktops.

### Proactive work and Action required

The desktop operating rules direct the model to continue through authorized safe steps until it verifies the requested result, rather than abandon a task after the first recoverable UI failure. Recovery must be materially different, state-verified, and bounded; uncertain input must never be replayed. A local non-executable text tab plus clipboard is a supported Unicode fallback when semantic text is unavailable; verify keyboard layout and the full local URL before navigating, and never send private text to a search engine/conversion service.

The model-only `desktop_request_user` tool records a **genuine user-only blocker** (`login`, `mfa`, `captcha`, `approval`, `clarification`, or exhausted `technical` recovery). It takes a short concrete instruction without secrets, displays that step in Pi, and marks the final outcome **Action required**, not completed. Subsequent desktop tool calls are blocked until a new user prompt, except metadata, handoff, and emergency Stop; same-message sibling desktop actions are blocked before execution; it cannot cancel an action from an earlier message already in flight. At final settlement the OS notification title is `Pi · Action required`, with a generic private-data-free body and expiry 0 (the desktop service may override expiry). The ON bar retains `Action required` beside the last duration. User abort and Stop still suppress all OS notifications. The model must explain what needs doing, end the turn, and resume after the user's reply by re-observing in this same session. The user authorizes browser-native saved-password autofill and submitting the login form for the verified intended site/account as part of a requested task (unless that task forbids login). An ordinary matching saved login is therefore not itself a user-only blocker. No password extraction/reveal/copy/logging, credential-vault access, password changes, or account creation is authorized. Missing/ambiguous saved logins require handoff; MFA/2FA, OTP, device/passkey approval, and CAPTCHA always require the user to act directly, then reply so the model can re-observe and continue. No code retrieval from messages, background polling, autonomous nested model, or security bypass is implemented or authorized. This is an explicit model handoff mechanism, **not** a guaranteed classifier for every login screen; autonomy is limited by the user's permissions and the actual desktop tools.

At final `agent_settled` (not intermediate turns or `agent_end`), the extension uses Linux `notify-send` to issue one generic desktop notification for an ON-mode run or a run that executed permitted desktop tools. Ordinary OFF-mode replies and OFF-mode metadata-only ping/metrics do not notify. User aborts and emergency Stop are completely silent: no notification subprocess and no delivery warning. Shutdown/reload discard unfinished activity. Notification bodies contain no prompt or private UI contents, and completion does not claim that the requested task succeeded: read the answer in Pi. Missing notification support is best-effort with one UI warning; Linux requires `notify-send` (usually `libnotify-bin`) and a desktop notification service. The subprocess uses fixed arguments, no shell, and a two-second timeout. The daemon and its protocol are unchanged; `desktop_request_user` is extension-local and sends no daemon command.

Use `/computer-use <task>` while ON to submit a user message in **this same Pi session** with desktop-only operating instructions already provided by the ON system section. Only verbatim task text is sent as a user message, avoiding duplicated rules in history. While OFF the command refuses submission and never auto-enables the mode. When the agent is busy, it queues as a follow-up rather than interrupting the current run. `/computer-use` shows help and registered/active tool counts; `/computer-use models` shows routing selection/phase. The redundant `status` aliases and the `instructions` display command are removed; operating rules remain injected automatically while ON. Help reports tool availability, **not** daemon connectivity or input state (use `desktop_ping` to check those). The command does not launch a daemon, start the workflow glow, or execute desktop input by itself; desktop tool calls start the daemon if needed and acquire their activity lease only after it is ready.

For optional CLI loading, `scripts/run-pi.sh` simply executes your installed `pi --extension <absolute index.ts path>`; it does not build Pi. Project auto-discovery also works when Pi runs in this repository with project trust granted, but does not descend into child projects from the user's home directory.

### Daemon version management

Before UI/AT-SPI tools acquire a workflow lease, the extension sends the metadata-only `daemon_info` handshake. It checks the direct-property safety fix and other required capabilities; a legacy/unknown response blocks observation before it can crash a browser. Ping, metrics and emergency Stop remain available without UI/version probing.

The extension compares a stable source-derived build ID with the ready binary's offline `--build-info` response. It checks an embedded offline-probe marker before executing that flag, so an older binary cannot accidentally start a second desktop backend. Owned daemons receive a random management token on spawn; private 0600 owner records persist PID, instance identity and token across `/reload`. Tokens never appear in tool responses. Only an authenticated **idle** daemon can accept `shutdown_if_idle`; the extension waits for graceful exit and starts the verified replacement before sending the desktop action once. Active workflows, a busy daemon or emergency-stopped input prohibit replacement. Compatible externally managed daemons are left running. Updates are checked lazily at tool execution, not by background restart timers or at extension load.

**Migration limitation:** daemons from before this handshake have no authenticated ownership/idle protocol. The extension detects and blocks them, but cannot safely auto-kill them. They require a one-time controlled migration; after a managed daemon is started, later safe updates are automatic. No browser profile/settings change or new Pi session is involved.

### Lazy daemon startup and safety

The extension performs **no socket/process work at load, session start, or `/computer-use` help**. Each normal desktop tool first checks Unix socket availability, then starts the daemon only for `ENOENT`/`ECONNREFUSED`. UI tools additionally complete the metadata-only safety/version handshake before acquiring a lease or inspecting the desktop. `desktop_stop` never starts it. If Stop arrives while a daemon is still starting and the immediate Stop request finds no socket, startup sends that explicit Stop as soon as the socket becomes reachable, **before** releasing queued tool calls; those calls fail without dispatching their actions. Even when Stop preempts this Pi's own spawn, it watches only until that startup attempt's original 12-second deadline for another Pi's lock winner to bind, then stops watching without spawning anything. If the delayed Stop cannot be confirmed, use the emergency hotkey and verify `desktop_ping`. Later input tools remain blocked in this Pi runtime even if the daemon is manually restarted. Stop against an already-running daemon is not delayed by startup. Polling is bounded to 12 seconds on cold start; concurrent calls in one Pi runtime share startup, and the daemon's socket lock resolves competing Pi processes. The first actual desktop action is dispatched **once**, only after readiness; connection timeouts or uncertain input outcomes are never retried. If another listener accepts connections but responds incorrectly, it is not replaced. Permission errors and uncertain probes refuse startup. The daemon remains running across Pi reload/shutdown; there are no background restart timers. After `desktop_stop` (or an `input_stopped: true` response or native stopped-input rejection), this extension runtime will not autostart a dead daemon or send further input. When safe, deliberately restart the daemon and use `/reload` in **this same Pi session** to reset the extension; a new Pi session is not required. The emergency hotkey still permanently stops input in a running daemon.

Startup errors include the attempted binary/socket and a private startup diagnostic path (`~/.local/state/pi-computer/daemon-startup.log`). For missing `DISPLAY`, invalid TOML, or missing binary, inspect that error/log, build with `scripts/install.sh` if necessary, or run `scripts/run-daemon.sh` in a terminal for foreground diagnostics. An independently running daemon is never killed or unlinked by Pi. The repository is resolved from the extension module path, not the current Pi working directory.

## Same-session model routing and image policy

`/computer-use models hybrid` enables extension-local physical routing without changing the standard `/model` selection; `models single` uses the selected physical model for all work; bare `models` reports phase and targets. Routing details appear only alongside Computer use ON in its existing above-editor widget, never as a virtual model or extra standard-footer status. While OFF the routing widget is hidden. Native `pi.setModel` handoffs change the real physical selection during a task; the host footer keeps showing that real model. Settlement restores the starting physical model only when the extension still owns the selection, including Stop/abort; manual changes are preserved. Old persisted virtual selections migrate to their saved authenticated physical model. Hybrid automatically resolves only authenticated models on the current physical selection's provider/account: retain the current Sol or choose the newest numeric-version Sol, prefer its exact paired Luna or choose the newest numeric-version Luna, and use a stable ID tie-break. No manual provider/ID commands or list/status aliases remain. Missing models fail without selecting another account. Switching the physical model/account in `/model` and enabling hybrid again recomputes targets; no credential files are read by this routing code. No nested model calls, classifiers, or production child sessions are used. Sol makes a semantic plan, `desktop_model_phase` hands it to Luna inside the same native run, and one explicit verified-blocker escalation returns to Sol without another bounce. Planning mutations are blocked; Stop remains available. Retries do not themselves change phase, ordinary OFF prompts keep the selected physical model, and compaction does not perform a handoff. A failed planning-model selection disables desktop tools and injects an explanatory failure section; it does not rely on lifecycle-handler exceptions to abort a model request. Preferences and phase follow branch-local custom metadata, not global settings. Model changes and actual physical dispatch are visible in the host. See [README usage](../README.md#sol-planning-luna-execution); no cost improvement has been measured.

Capture tools require one exact `desktop_visual_permission` before each image, including `desktop_observe` with `screenshot:true`. The model must cite an explicit user request or a concrete semantic blocker plus bounded AT-SPI/window/GIO checks. Grant and capture cannot share an assistant tool batch; use a live node crop or smallest useful rectangle. Full screen needs a stated layout requirement/request. Permission is consumed before dispatch checks and cleared on abort, settlement, or next run; failed/uncertain capture never leaves a replayable permit. The declaration remains model-provided evidence, not independent intent classification or a general sandbox. OFF gates apply to permission and capture alike.

## Settings and configuration

The daemon reads TOML from `COMPUTER_USE_CONFIG` when set (an explicit missing/unreadable file is an error). Otherwise it reads `$XDG_CONFIG_HOME/pi-computer/config.toml` or `~/.config/pi-computer/config.toml` if present, and uses built-in defaults if absent. `scripts/run-daemon.sh` sets `COMPUTER_USE_CONFIG` to the repository's [config/default.toml](../config/default.toml) unless already set, so edits to that file take effect when using the script. To use the user config with the script, set `COMPUTER_USE_CONFIG` to its path. Invalid TOML or invalid settings stop startup before socket creation.

Supported `[daemon]` keys: `socket`, `overlay` (boolean, default `true`), `tile_size` (integer 1..=65535, default `64`, for incremental visual crops and root dirty-region detection), and `debug` (boolean, default `false`, prints startup settings). `socket = "${XDG_RUNTIME_DIR}/pi-computer.sock"` uses the runtime-directory default described above, including the `/run/user/<effective-uid>` fallback. `socket_mode` must be `"0600"`; socket permissions are fixed. `[client].timeout_ms` in the example is documentation only: the Pi extension does **not** read TOML.

The optional `[overlay.edge]` table configures the monitor-edge glow: `color` (`#RRGGBB`), `width` (1..=64 pixels), `blur` (0..=64 pixels), and `opacity` (0.0..=1.0). `[overlay.cursor]` configures the pointer halo: `color` (`#RRGGBB`), `radius` (16..=128 pixels), and `opacity` (0.0..=1.0). The [reference config](../config/default.toml) uses a blue `#4198F7` edge (2-pixel core, 28-pixel Gaussian blur, opacity 0.22) and a single antialiased Gaussian pointer halo (radius 40, opacity 0.38). `[overlay.animation]` accepts `enabled` (default true), `period_ms` (400..=10000, default 1600), and `fps` (10..=30, default 30). Brightness breathes smoothly between 35% and 100% of configured edge/cursor opacity; it never vanishes. The actual cursor is unchanged; the halo is click-through. No-config built-in settings match the reference style; omitted keys use those defaults. Styles are validated at startup even if the overlay is disabled.

Environment variables override daemon TOML values:

- `COMPUTER_USE_SOCKET`: socket path; daemon and extension both honor it. Lazy startup forces the spawned daemon to use the extension client's exact socket even if TOML specifies another.
- `COMPUTER_USE_AUTOSTART=0`: disable extension startup (tools still connect to a manually started daemon).
- `COMPUTER_USE_DAEMON`: explicit absolute executable ELF daemon binary override (scripts are rejected); otherwise use this repository's release binary, then `~/.local/bin/pi-turbo-daemon`. No Cargo or shell execution occurs during tool calls. A missing binary is reported without dispatching the action.
- `COMPUTER_USE_CONFIG`: explicit daemon config path, preserved for lazy startup; otherwise the repository's `config/default.toml` is used when present (as with `scripts/run-daemon.sh`).
- `COMPUTER_USE_OVERLAY`: optional visual feedback (`1/0`, `true/false`, `yes/no`, `on/off`, case-insensitive).
- `COMPUTER_USE_TILE_SIZE`: visual crop and root dirty-region tile size (1..=65535).
- `COMPUTER_USE_DEBUG`: startup diagnostics (same boolean values as overlay).
- `COMPUTER_USE_TIMEOUT_MS`: extension-only request timeout in milliseconds (default `30000`).

The daemon validates configuration even in `--stdio` mode. The extension still selects its socket independently via `COMPUTER_USE_SOCKET` or its own default; a TOML-only socket change requires setting that environment variable for the extension too.

## Tests and benchmark

Measured results and limits: [PERFORMANCE.md](PERFORMANCE.md). An earlier measured release milestone had dirty-region p50 about 1.58 ms versus 15.98 ms before optimization (100 requests); this is daemon IPC, not model latency or billing.

```sh
tests/test-ipc.sh
tests/test-run-profile.sh  # offline release/debug launcher check
~/.cargo/bin/cargo test --manifest-path daemon/Cargo.toml live_visual_feedback_activity_capture_stop_and_cleanup -- --ignored  # optional compositor overlay test, no input
~/.cargo/bin/cargo test --manifest-path daemon/Cargo.toml live_unix_ipc_activity_lease_whole_workflow -- --ignored  # own overlay/socket; thinking, renewal, capture suspension, expiry, Stop; no input
```
