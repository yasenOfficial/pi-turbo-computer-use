# Execution-strategy regression fixtures (offline)

Run `node --test tests/test-execution-benchmark.mjs` and `node scripts/benchmark-execution-strategy.mjs [--samples 1..20]`. Optional isolated browser replay: `node scripts/benchmark-execution-strategy.mjs --gui`; regression test: `PI_EXECUTION_GUI_TEST=1 node --test tests/test-execution-benchmark.mjs`. No provider, user desktop input, personal browser profile, remote site, or login is touched. The CLI-only runner creates uniquely named temporary **test-owned** files, checks their contents/stdout, and removes them. Its fixed Python program runs with isolated Python options and a restricted environment. The GUI wrapper compiles the working-tree daemon offline, starts its own Xephyr as a test-owned process on the parent display, and exposes **only that nested X socket** to the worker in a disposable private PID/network/mount namespace. The worker's `/home` and `/run` are masked before mounting only this checkout read-only at its original path; its `/tmp`, `HOME`, XDG runtime/profile/config/data and DBus session are private. Direct `--worker` invocation fails closed when display, runtime, or credential guards fail. The only network traffic is to the fixture loopback HTTP server. This is a restricted test fixture, not a general-purpose security sandbox: the authorized working-tree sources/binary remain readable and Xephyr itself connects to the parent X server. The shell/IPC is restricted to this isolated test-owned fixture, not end-user tasks; its native daemon IPC operations are **not registered Pi SDK tool invocations**. The only clipboard operation is the gated native paste inside the disposable X display, never the host selection. The runner emits aggregate JSON to stdout only; **do not commit reports without inspecting them**.

A reviewed single-machine eight-case fixture report (three CLI repetitions; one GUI replay) is `benchmarks/execution-strategy-isolated.json`. All eight **fixtures** passed in that run, not eight model tasks. Times are environment-dependent. It also includes a separate, controlled same-binary input comparison described below; that limited comparison does **not** turn task-level timings into a before/after agent benchmark. The source baseline is commit `04cd834`, loaded by `git show 04cd834:<path>`, never the concurrently changing checkout. The report contains SHA-256 fingerprints of the baseline and working-tree instruction, routing, tool-registration and native-input *sources*; newly added clipboard module has a `null` baseline fingerprint. Optional GUI replay also reports SHA-256 of the executable it launched, but a concurrent rebuild can still break source↔binary attribution. A static policy regression test checks CLI-first vs baseline Sol handoff and preserves explicit GUI intent; it does not execute an agent. `baseline_native_binary_identity: null` is deliberate: an installed release daemon may have a different Rust build or TS extension. These hashes cannot attest executable identity. No runnable baseline/optimized agent cohort is included.

`fixture_execution` is **not** agent tool choice, a native Pi SDK tool call, or a strategy comparison: CLI-only operation count includes actual instrumented Node filesystem operations / fixed Python spawn. CLI-only wall time is measured with `performance.now()` for operation **and verification**, median and nearest-rank p95 for 1–20 samples; it excludes startup/provenance. `--gui` performs one local GUI replay (not repeated samples): GUI `wall_ms` includes native IPC, semantic discovery and result verification, **not** browser/daemon startup or model latency. `daemon_requests` counts all actual native IPC round trips (including semantic reads); `input_dispatch_requests` counts actual requested native input commands, not low-level keyboard events. `reported_paste_keyboard_events: 4` is reported by the native paste response for the form only; other clicks' keyboard events are unknown. `image_blocks: 0` is measured on the fixture IPC replies only, not model vision tokens. `desktop_calls: 0` describes just the three no-desktop fixtures. Model messages/tokens, billed cost and quota remain unknown (`null`); `agent_tool_calls: null` for GUI because it calls native IPC in a **private fixture**, not Pi SDK tools. `baseline` and `optimized` are `null` in *every* task case. Without `--gui`, GUI cases are `skipped`, not successful; when isolation is unavailable they remain skipped. With `--gui`, five GUI cases are individually verified or explicitly failed/skipped, not inferred from a browser launch. No performance reduction, quota savings, or 8/8 task success can be inferred.

## Controlled old typing vs new paste: actual private-browser event counts

On the same isolated Firefox page, two different test-owned empty text fields receive the **same 150 lower-case ASCII characters**. The first field is filled by the old physical `type`/`set_text`-without-id protocol path. The second is filled by the new clipboard-backed `paste_text` protocol path with a freshly verified focused semantic target. After each action, the runner checks AT-SPI text and clicks a native semantic verification button; the fixture's own page posts the exact value and only the counts of **trusted DOM `keydown`, `keyup`, and `paste` events** to its loopback HTTP server. Neither the runner nor external automation modifies a browser DOM field. The server checks the exact value before retaining only counts; it never saves text.

The checked-in report observed **150 keydowns + 150 keyups, zero paste events** on the legacy path versus **2 keydowns + 2 keyups, one paste event** on the new path. The daemon separately reported four paste shortcut key events. These are *observed events in the private page*, not inferred `2 × text length` and not global X11 keyboard telemetry. Both fields reached the exact same verified value. `legacy_type_text_source_unchanged` compares the pinned `04cd834` typing function, physical-text validation, event and keysym helpers, and primary-group mapping lookup **by their individual function bodies** to the current source (paste-only methods inserted between them are excluded) before attributing this retained path to baseline code; the executable in the fixture was nevertheless **only** the freshly built working-tree native daemon. No runnable baseline daemon, old extension, old agent run, native Pi SDK `desktop_*` invocation, real model, model image tokens, or billing was measured. Wall times cover discovery/verification as well as input and are single observations, not a statistical speed claim. Unicode round-trip is separately verified by the browser-form fixture, not by this ASCII-only differential test. If the pinned old typing code changes, the comparison is not eligible rather than silently attributing a different implementation to baseline.

## For a genuine comparison later

Run the **same fixed, authorized task** in independent fresh Pi sessions, from a separately verified build of each pinned source tree, with isolated test-owned desktop, clipboard and profile; never direct a script/IPC to act on the user's desktop. Check native binary provenance against the actual built artifact; the executable currently installed is not automatically baseline. Use the native Pi SDK/provider integration and registered `desktop_*` tools for GUI actions, no injected shell/DOM bypasses, and record observed tool calls (including non-desktop read/write/edit/bash calls), root tool-result image blocks, input events only when independently instrumented, verified outcomes, errors, and source/build IDs. Do not call a scripted fixture a model decision or invent a baseline GUI gesture count. Obtain browser form readback through the private fixture, keep origin loopback-only, and assert Bulgarian Unicode round-trip rather than assuming paste succeeded. If a private display, browser, editor, or VS Code is absent, skip that case explicitly; never fall back to the real display or personal profile. Separate source versions, tool policy, fixture, and provider/model/reasoning settings; alternate order, reset state, and report failed/unrated runs. See `docs/TASK-COMPARISON.md` for opt-in real Pi session debug reports, their eligibility rules, unknown usage, and limits. Do not publish screenshots, prompts, raw clipboard/form data, credentials, profiles, logs, or diagnostic dumps.
