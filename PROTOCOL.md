# Daemon ↔ extension protocol

The daemon and Pi extension exchange one newline-delimited JSON request and response per Unix-socket connection. The socket is `$COMPUTER_USE_SOCKET`, otherwise `$XDG_RUNTIME_DIR/pi-computer.sock` (normally `/run/user/$UID/pi-computer.sock`). The daemon creates it with mode `0600`. Coordinates are absolute X11 screen coordinates. The extension's model-facing observation is a compact view, not the full IPC tree: exact active-window matches are scoped when safe; unscoped overviews default to 24 top nodes and a 6,000-character budget, with generation and explicit omission counts retained. Raw daemon snapshots/history remain complete within traversal bounds. Use `search_seen` followed by live `inspect` to resolve omitted controls; do not interpret omission as disappearance. A bounded 180-ms probe can retain a real Cinnamon shell stage when observed showing menu/focused search states prove activity despite another active window. Model output uses `semantic_scope:"active_window_with_shell"` and `shell_scope_roots` when linked Cinnamon popup nodes are proven; hidden/idle or unlinked shell controls do not qualify. This conditional behavior has fixture coverage, not verified live Cinnamon menu availability.

Before a normal tool request, the extension probes the socket without sending a command. On `ENOENT`/`ECONNREFUSED` it may start an existing release binary with the client's exact socket path; no shell, Cargo build, or action retry is used. Startup is bounded to 12 seconds and shared by concurrent callers. `desktop_stop` never starts a daemon. Socket-mode daemon startup holds an owner-only `<socket>.lock` file lock before probing stale sockets or initializing desktop backends, and binds the socket only after initialization. The lock inode is kept on disk to prevent lock-replacement races; it is unlocked when the process exits. Stdio mode does not claim a socket lock. Pi reload/shutdown does not terminate a ready daemon, and lease renew/end never trigger startup.

`daemon_info` is metadata-only and bypasses the action mutex: `{ok:true,daemon_info:{protocol_version,build_id,pid,instance_id,managed,input_stopped,active_workflows,busy,capabilities}}`. Build IDs are stable 16-hex source hashes; instance IDs are random 32-hex values. Required safety capabilities include `atspi_direct_properties`, `verified_focus` and `launch_app`. The offline `--build-info` command emits build metadata before config or desktop initialization. Its embedded `probe_marker:"pi-computer-build-info-v1"` identifies binaries safe to execute for that offline probe.

`shutdown_if_idle` accepts `{cmd:"shutdown_if_idle",instance_id:"...",token:"..."}` on Unix IPC only. The token must match the private `COMPUTER_USE_MANAGED_TOKEN` supplied at daemon spawn and the instance must match. Neither field can authorize input. Unmanaged, stopped, busy or leased daemons refuse shutdown. Successful acknowledgement is flushed before graceful exit; closing fences new activity and input. The extension never signals an arbitrary daemon process and never retries a desktop action as part of upgrade. Private owner records authenticate later upgrades across Pi reload; unknown legacy daemons are blocked from UI observation, not forcibly replaced.

`ping` returns `{ "ok": true, "input_stopped": false }` (or `true` after emergency stop). `observe` reads the accessible UI tree and returns a `snapshot` or, when `since` is supplied, a `delta` when that generation is retained. It is semantic-only by default; `{ "cmd":"observe", "screenshot":true }` opts into a PNG. `changes` uses its explicit `since`, or the daemon's last-observed generation when omitted. An unchanged semantic tree retains its generation. `wait` accepts `since` and `timeout_ms` (default 30000, maximum 120000), wakes for AT-SPI events, and returns a snapshot/delta (including an empty delta on timeout). `inspect` requires `id` and returns `node`.

Input/action requests (`click`, `double_click`, `drag`, `focus_window`, `set_text`/`type`, `keypress`, and `scroll`) return acknowledgements, not an accessibility snapshot. The action invalidates the accessibility cache; a subsequent `observe`, `changes`, or `wait` refreshes it and computes any delta. `focus_window` uses an EWMH pager-source activation request and waits up to one second for the target's real `_NET_ACTIVE_WINDOW` acknowledgement, checking safety between polls. It reports refused focus or a vanished window as an error; it does not promise the user cannot change focus after acknowledgement. No close request or synthetic click is sent. Semantic IDs (`n1`, `n2`, …) are daemon-lifetime references; observe again after actions or if an ID is stale. `stop` permanently disables further daemon input until restart; it does not stop the process. It bypasses the action mutex and wakes waits immediately. Native gestures check the flag between events and best-effort release their synthetic presses; a stop acknowledgement does not mean all in-flight cleanup has finished. A timed-out/disconnected input request may already have partially executed and must not be retried automatically. Physical typing is capped at 16,384 characters; direct semantic editable text is separate.

`launch_app` accepts exactly one selector: `{"cmd":"launch_app","app_id":"brave-browser.desktop"}` (if installed), or `{"cmd":"launch_app","name":"exact localized display name"}`. `app_id` is an ASCII desktop ID basename ending in `.desktop`, at most 240 bytes, with only letters, digits, `.`, `_`, `-`, and no leading dot; `name` is the exact installed visible application's localized display name (nonblank, no control characters, at most 240 Unicode characters). No executable command, desktop-file path, arguments, or extra fields are accepted. The daemon resolves only visible installed GIO desktop entries and dispatches through native GIO; it never runs a model-supplied command. Success returns `{"ok":true,"launch":{"app_id":"brave-browser.desktop","name":"Brave Web Browser","accepted":true}}` (the name reflects actual installed metadata, not a guaranteed spelling). `accepted` means dispatch was accepted, **not** that a window exists or is ready: wait/observe afterward. An ambiguous name returns `{"ok":false,"error":"ambiguous desktop application; use app_id","app_matches":[{"app_id":"…desktop","name":"…"}]}` with up to 20 exact matches and no dispatch. Missing entries return `ok:false` with an error and no automatic retry. This is a standalone action (not a `batch` step), requires no XTEST for GIO resolution/dispatch, is blocked by emergency Stop, and acquires the Pi workflow lease like other action tools. The final atomic safety check is the launch's in-flight boundary: Stop after that check may precede the actual GIO call but cannot cancel it or undo dispatch. Stop stays responsive and rejects subsequent gated launches; its acknowledgement is not proof that an in-flight launch has been cancelled. A timed-out/disconnected request or malformed reply has uncertain outcome and must not be retried automatically. The extension can lazily start a missing daemon before sending a desktop action, but never replaces a working listener or automatically re-enables stopped input.

`inspect_visual` without `incremental:true` returns `png_base64` for the screen or the bounded crop identified by `id`. Incremental mode requires an accessibility `id`: the first request (or a missing/stale revision or changed ID/bounds) returns a full visual baseline; pass its revision as `since_visual` on later requests. The response's `visual` contains `full`, `revision`, crop coordinates/dimensions, `tile_size` (64), and `patches` containing changed PNG tiles in absolute root coordinates. Revisions are daemon-lifetime; discard them after daemon restart. `full:false` with empty patches means unchanged. This is an on-demand visual cache: each request captures and compares a bounded crop and returns merged changed tiles. It does not poll in the background and is not an XDamage event stream or video capability.

`metrics` accepts `{"cmd":"metrics","reset":false}` and returns `metrics: {stages,capture_mode,capture_transport,transferred_pixels,capture_count}`. Each bounded stage has `{count,samples,total_us,p50_us,p95_us}`; percentiles are nearest-rank over the most recent 256 samples, while count/total cover the interval since reset. `reset:true` returns the report before clearing it. Stage times may overlap (e.g. capture contains acquisition/hash); do not sum all stages as independent costs. Pixels are area estimates, not measured X11 wire bytes. Metrics carry no UI names, query text, or images and are omitted from normal responses.

`search_seen` accepts `{"cmd":"search_seen","query":"Save","limit":10}` (limit 1–50; query 1–240 characters) and returns `seen: {generation,results:[{id,name,role,bounds?,window?,last_seen_ms,generation,source}]}`. `source` is `current` or `stale` relative to the most recent AT-SPI observation; the request refreshes observation before searching. It searches a daemon-lifetime, in-memory index with a 2,000-entry/30-minute cap (10 results by default), ranks exact names above prefix/token/substring matches, and refreshes unchanged-index timestamps without rebuilding metadata. It retains no editable field names/values or images, and no disk persistence. Names/window titles may themselves contain sensitive text. Hits are hints: before using an ID for input, reobserve and verify the current target; a historical hit may refer to a closed window.

`batch` accepts 1–24 ordered nonvisual actions (`type` = `click`, `double_click`, `set_text`, `keypress`, `scroll`, `drag`, `focus_window`, `wait`) with `stop_on_error` and `include_changes` (both default true). Click/text actions accept either `id` or `target` (`id`, exact `role` and/or exact `name`); an ambiguous or missing target fails safely. Wait accepts `condition` (id/name substring/role) and `timeout_ms`, releases the daemon lock while waiting. `batch.steps` reports step types, status, elapsed milliseconds, optional match/errors; `batch.completed` marks whether every step ran. `changes` is the direct net semantic delta from before to after the whole batch. Failed batches report partial steps and do **not** roll back earlier actions. The Pi extension exposes this as `desktop_batch` and preserves step status on failure.

`dirty_regions` is an **explicit, on-demand** metadata-only request. It reads one native full-root X11 ZPixmap frame, hashes configurable 64×64 tiles with xxHash3 directly (without RGBA conversion, excluding scanline padding and unused XRGB bits), and compares them with the preceding successful `dirty_regions` request. Response `screen_diff` contains `{revision,capture_mode,baseline,screen_width,screen_height,tile_size,dirty_tiles,regions,summarized}`. Each entry of `regions` is an absolute root-window `{x,y,width,height}` rectangle formed by merging adjacent changed tile runs horizontally and equal-width runs vertically, across the whole screen with no quadrant boundaries. The first request or a resize returns `baseline:true` and one region covering the whole screen; unchanged frames return `regions:[]` and `dirty_tiles:0`. If merging would produce more than 64 regions, `summarized:true` and a conservative single bounding rectangle cover all dirty tiles. There is **no image data** in this response. The click-through overlay is synchronously suspended before capture to avoid self-induced diffs, and resumes its existing animation phase afterward if an input action/batch or workflow lease remains active. The acknowledgement is an X-server unmap barrier, not a universal compositor presentation fence; an asynchronous compositor may still have a previous output frame. The daemon can subscribe to root XDamage hints, but root drawable damage is **not** a complete notification source under Cinnamon/Muffin's redirected windows and compositor. Each request therefore still captures the raw **full root** frame (`capture_mode:"full_root"`), even with an empty damage event queue. Tile-aligned partial capture exists as a guarded internal path for a future independently complete damage source, but is not activated by root XDamage. Full-frame checks reuse a bounded RAII MIT-SHM buffer locally, falling back to GetImage; both still scan all root pixels. There is no background polling. Animations, clocks, and pointer movement can cause unrelated regions to change.

Example IPC:
```json
{"cmd":"batch","actions":[{"type":"wait","condition":{"name":"Save As","role":"dialog"},"timeout_ms":3000},{"type":"set_text","target":{"role":"text","name":"Name"},"text":"example.txt"},{"type":"click","target":{"role":"push button","name":"Save"}}]}
```

Visual feedback combines scoped activity for input requests/batches with expiring workflow leases. The Pi extension acquires one lease at the first desktop tool execution (excluding ping, metrics, Stop), retains it during model thinking, renews every 10 seconds, and ends it at `agent_settled`, abort, shutdown/reload, or Stop. `agent_end` alone is not a final workflow boundary. Concurrent capture temporarily suspends the overlay and restores ongoing activity afterward. Brightness/period/frame rate remain configured in TOML.

`control_activity` is **internal extension-to-daemon IPC**, not a model tool. It is handled outside the action mutex and is accepted only on the local Unix socket (not `--stdio`). Requests:
```json
{"cmd":"control_activity","action":"begin","token":"00112233-4455-6677-8899-aabbccddeeff","ttl_ms":30000}
{"cmd":"control_activity","action":"renew","token":"00112233-4455-6677-8899-aabbccddeeff","ttl_ms":30000}
{"cmd":"control_activity","action":"end","token":"00112233-4455-6677-8899-aabbccddeeff"}
```

Tokens must be 36-character ASCII UUIDs; each workflow generates a fresh random token. TTL defaults to 30,000 ms and must be 1,000–60,000 ms. `end` must not include `ttl_ms`. At most eight leases are retained. Duplicate begin and unknown/expired renew fail; end is idempotent. Responses use `{"ok":true}` or `{"ok":false,"error":"..."}`. A 100-ms reaper expires leases even without a connected client; Stop clears them and rejects new begin/renew. Leases never grant input permission or clear sticky safety. With `overlay=false`, lease bookkeeping still works without a visual. Scoped action tokens and other workflows coexist; closing one lease does not hide another. Older daemons lack this command and cannot provide workflow-wide indication.

The X11 emergency hotkey is **Ctrl+Alt+Esc** (Ctrl+Alt+Shift+Escape fallback if unavailable). It disables daemon input until restart; if its passive X11 key grab cannot be installed, the daemon logs a warning and the `stop` request remains available. AT-SPI and a working session bus are required for accessibility commands; X11 capture/input are separately dependent on a reachable X server (and input on XTEST). The implementation is X11-only; behavior and availability depend on the desktop, application accessibility support, and current session configuration.
